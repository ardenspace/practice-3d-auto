# vanished-worlds 설계 문서

작성일: 2026-09-02
상태: 사용자 검토 대기
작업명: `vanished-worlds` (채널명이 확정되면 폴더명과 함께 변경한다)

## 1. 프로젝트 목표

사라진 장소들을 담은 하나의 허구 세계를 배경으로, 움직이는 앰비언트 영상을 최대한 무료 도구로 자동 생성하는 유튜브 채널 파이프라인을 만든다.

- 수익화가 진짜 목표다. 수익의 본체는 가로 롱폼 앰비언트 영상(20분~1시간, 작업용·수면용)이고, 세로 쇼츠는 유입 트레일러로 쓴다.
- 정적 이미지 슬라이드쇼가 아니라, 실제로 움직이는 장면(카메라 이동, 안개, 입자, 조명 변화)을 만든다.
- 사람이 개입하는 지점은 세 곳으로 제한한다: 소재 회의, 프리뷰 스틸 승인, 업로드 전 확인.
- 기존 auto-shorts 코드는 참고하지 않는다.

### 수익 전략의 근거

- 2026년 기준 쇼츠 광고 RPM은 조회수 1,000회당 $0.01~0.07 수준이라, 쇼츠 광고 수익만으로는 채널이 성립하지 않는다. 롱폼은 RPM이 수십 배 높고 시청 시간이 누적되므로 수익의 본체가 된다.
- 폐허·꿈속·사라진 장소 세계관은 해외의 리미널 스페이스(liminal space) 장르와 겹치며, 수요가 실재한다(backrooms 제목 영상 연간 20억 회 이상 조회). 이 장르의 시청자는 얼굴 없는 채널과 분위기 중심 영상을 선호한다.
- 리스크: 유튜브는 2025년부터 대량 생산된 반복성 콘텐츠의 수익화를 제한한다. Blender로 실제 연출된 움직임과 회차마다 다른 세계관 장면은 이 기준에서 변별력이 있지만, 완전 무인 대량 생산으로 갈수록 리스크가 커진다. 초기에는 사람의 승인 게이트를 유지한다.

## 2. 세계관과 채널 정체성

### 프레임 장치: 사라진 것들의 세계 + 기록자 문체

세상에서 잊히거나 사라진 장소는 소멸하지 않고 어떤 경계 너머의 세계에 도착한다는 설정을 뼈대로 한다. 실존했던 수몰 마을도, 누군가의 꿈에서 사라진 도서관도 같은 자격으로 이 세계에 존재하므로, 실존 기반 소재와 순수 허구 소재를 하나의 채널에 담을 수 있다.

그 세계를 걷는 기록자가 있고, 채널명·영상 제목·설명란·썸네일 문구·쇼츠 훅 자막은 기록자의 1인칭 관찰 문장으로 쓴다. 화면 속 자막이 아니라 영상 바깥의 텍스트에서 작동하는 장치다. 회차가 쌓일수록 채널 전체가 하나의 세계 지도처럼 탐색되는 것이 포화된 앰비언트 시장에서의 주된 차별화 수단이다.

기록자 자신의 이야기는 나중에 세계관을 확장할 때의 서사 축으로 남겨 둔다.

### 영상 형태

- 롱폼: 화면 텍스트 없음. 감상용 영상에서 텍스트는 방해 요소다.
- 쇼츠: 기록자 문체의 훅 자막을 끌 수 있는 레이어로 만든다. 같은 영상을 자막 있는 판과 없는 판으로 뽑아 성과를 비교하는 실험이 거의 무비용이므로, 파일럿 데이터를 보고 기본값을 정한다.

## 3. 장면 제작 전략: 하이브리드

한 회차는 4~6개의 샷으로 구성하며, 두 기법을 섞는다.

### 기본 기법: 2.5D 패럴랙스

Codex로 장면 이미지를 생성하고, 깊이 맵을 추출해 Blender 카메라에 투사한 뒤, 느린 카메라 이동(푸시인, 팬)과 안개·먼지·빛 입자를 얹는다. 매 회 완전히 새로운 비주얼을 빠르게 만들 수 있다.

- 깊이 추출은 로컬 무료 모델 Depth Anything V2를 쓴다. Apple Silicon에서 로컬 실행이 가능하다.
- 단일 이미지 깊이 추정의 약점(카메라가 크게 움직일 때 물체 가장자리가 늘어나는 왜곡)은, 이동 폭이 작은 느린 연출과 안개·얕은 심도로 가려지므로 이 장르가 이 기법의 최적 조건이다.
- 깊이 추출은 독립 모듈로 분리해서, 품질이 부족하면 대안 모델(Marigold, Depth Pro)로 교체할 수 있게 한다.

### 시그니처 샷: 3D 템플릿

템플릿이 확보된 뒤부터는 회차마다 한두 개의 샷을 실제 3D 장면으로 만들어 카메라가 공간을 통과하는 움직임을 확보한다. 만들어진 장면은 파라미터(조명, 안개 농도, 오브젝트 배치, 카메라 경로)를 바꿔 재사용할 수 있는 템플릿으로 `library/`에 쌓는다.

- 처음에는 2.5D 100%로 시작하고, 템플릿이 쌓일수록 3D 비중을 늘린다.
- 3D 에셋 확보 순서: ① Poly Haven(CC0 텍스처·HDRI·모델) 검색 → ② Poly Pizza / Sketchfab에서 CC 라이선스 모델 검색 → ③ 그래도 없을 때만 3D 생성(Hyper3D Rodin 무료 한도, Hunyuan3D)을 예비 수단으로 쓴다. 폐허·안개·실루엣 중심 장르라 정밀 소품이 필요한 장면 자체가 적고, 원거리 사물은 2.5D 카드로 처리한다.

### 장면 자산의 기준 규격

렌더는 가로(롱폼) 기준으로 만들고, 쇼츠는 그 프레임에서 세로로 잘라 쓴다. 샷 하나는 2~3분 루프가 가능하게 설계해서, 교차 배열·반복으로 목표 길이의 롱폼을 조립한다.

## 4. 파이프라인

한 회차는 일곱 단계를 거친다. 사람이 개입하는 게이트는 ①, ④, ⑦ 세 곳이다.

| 단계 | 주체 | 내용 |
|---|---|---|
| ① 소재 회의 | 사용자 + LLM | 대화로 장소를 정하고 에피소드 브리프를 저장한다 |
| ② 에셋 생성 | 자동 | Codex 이미지 생성, 깊이 추출, CC0 에셋 검색·다운로드 |
| ③ 프리뷰 렌더 | 자동 | 샷마다 대표 프레임 한 장씩 렌더 (몇 분 소요) |
| ④ 프리뷰 승인 | 사용자 | 스틸을 보고 승인하거나 샷 단위로 수정 지시 |
| ⑤ 본 렌더 | 자동 | 샷마다 2~3분 루프 영상을 헤드리스 Blender로 렌더 |
| ⑥ 합성 | 자동 | ffmpeg로 롱폼 조립 + 음악·환경음, 쇼츠 재단, 메타데이터 생성 |
| ⑦ 업로드 확인 | 사용자 | 완성본과 메타데이터 확인 후 업로드 |

### ① 소재 회의

- 회의 상대는 기본적으로 Claude Code 세션이다. 터미널에서 직접 하거나, 이미 연결된 텔레그램 플러그인으로 원격에서 한다. Blender 렌더 때문에 맥은 켜져 있으므로 세션 유지가 추가 조건이 아니다.
- 회의 상대가 누구든(헤르메스+코덱스 포함) 산출물인 브리프 파일의 스키마만 통일한다. 파이프라인은 브리프만 읽으므로 어느 쪽이든 동일하게 동작한다.
- 브리프 스키마: 장소 이름(세계관 내 지명), 사연(이 장소가 왜 사라졌는가), 무드 태그, 샷 구성(샷별 공간·시간대·카메라 이동), 색·조명 방향.
- Gemma가 후보 장소와 사연 초안을 미리 여러 개 생성해 두면, 회의는 고르고 다듬는 자리가 된다.

### ② 에셋 생성

- 브리프(한국어)를 입력으로 받아 Codex 이미지 생성용 영어 프롬프트, 에셋 검색 키워드, 필요시 3D 생성 프롬프트를 만드는 것은 파이프라인 안의 LLM 단계다.
- 자동 실행 시에는 로컬 Gemma가 정해진 템플릿으로 이 변환을 수행한다(무료 원칙). 파일럿 단계에서는 Claude가 직접 만들면서 템플릿 자체를 다듬어 Gemma에게 물려준다.

### ④ 프리뷰 승인

- 같은 장면에서 프레임 한 장만 뽑는 프리뷰 렌더(몇 분)와 전체 애니메이션 렌더(수 분~수십 분)를 분리하는 2단계 렌더 구조다. 승인 전에는 긴 렌더가 시작되지 않는다.
- 스틸은 텔레그램으로도 전송해서 외출 중에도 승인할 수 있게 한다.

### ⑥ 합성

- 목표 길이(예: 30분)의 롱폼을 샷 교차 배열로 조립하고, 무드 태그로 음악을 자동 선곡하며, 환경음을 밑에 깐다.
- 같은 재료에서 가장 인상적인 구간을 세로로 잘라 쇼츠 1~2편을 만든다.
- 제목·설명란·썸네일 문구는 Gemma가 기록자 문체로 생성한다.

### ⑦ 업로드

초기에는 수동 업로드로 시작하고, 안정되면 YouTube API 자동 업로드로 전환한다.

## 5. 도구별 역할

- **Blender**: 유일한 렌더 엔진. 헤드리스 CLI + 파이썬 스크립트로 자동화하고, Eevee 렌더러로 렌더 시간을 통제한다. 실행 파일: `/Applications/Blender.app/Contents/MacOS/Blender`. 파일럿 제작·장면 실험에는 Blender MCP를 쓰고, 반복 생산은 CLI로 한다.
- **Codex 이미지 생성**: 2.5D 패럴랙스의 원본 이미지, 텍스처, 썸네일. 최종 컷이 아니라 재료로 쓴다.
- **Gemma (로컬, llama-server 8080)**: 소재 후보·사연 초안 생성, 브리프→프롬프트 변환, 제목·설명·훅 자막 생성. 전부 무료.
- **Depth Anything V2 (로컬)**: 깊이 추출 독립 모듈.
- **ffmpeg**: 조립, 음악·환경음 합성, 쇼츠 재단, 자막 레이어.
- **three.js**: 제외한다. 인포그래픽이 없는 채널이라 쓸 자리가 없고, 헤드리스 캡처 파이프라인을 하나 더 유지할 이유가 없다.
- **TTS**: 없음. 내레이션이 없는 형태를 선택했다.

## 6. 음악과 사운드

원칙은 Content ID 분쟁 가능성 제로다. 소리는 두 층으로 나눈다.

- **음악 층**: YouTube 오디오 라이브러리와 CC0 음원을 미리 내려받아 `library/music/`에 무드 태그와 함께 쌓아 두고, 합성 단계에서 브리프의 무드 태그와 매칭해 자동 선곡한다. 초기 큐레이션(수십 곡)은 1회성 수작업이다.
- **환경음 층**: 바람, 빗소리, 물결, 모래 소리 같은 CC0 환경음을 장면과 매칭해 음악 밑에 깐다. 같은 곡을 여러 회차에 써도 영상마다 소리가 다르게 느껴지게 하는 장치다.

## 7. 저장 구조

```text
vanished-worlds/
├── world/        # 세계관 설정, 기록자 문체 가이드, 장소 등록부(회차가 쌓일수록 세계 지도가 된다)
├── library/      # 음악, 환경음, HDRI, 재사용 Blender 템플릿
├── episodes/
│   └── <장소-슬러그>/   # 브리프, 생성 에셋, 샷 정의, 프리뷰 스틸, 렌더 결과, 최종 산출물
└── pipeline/     # 단계별 스크립트, 브리프 스키마 문서
```

## 8. 실패 처리

- 각 단계는 이미 산출물이 있으면 건너뛰는 재실행 안전(idempotent) 구조로 만든다. 밤새 렌더가 중간에 죽어도 같은 명령 한 번으로 이어서 진행된다.
- 긴 렌더가 끝나거나 실패하면 텔레그램으로 알림을 보내고, 실패 시에는 로그 요약을 함께 보낸다.

## 9. 검증 계획 (파일럿 3관문)

구현은 세 관문을 순서대로 통과하며, 품질이 기준에 못 미치면 다음으로 넘어가지 않고 기법을 조정한다.

1. **패럴랙스 품질 테스트**: Codex 이미지 한 장 → 깊이 추출 → 카메라 투사 → 10초 움직이는 영상. 이 기법의 품질이 채널 기준에 맞는지 눈으로 확인한다.
2. **첫 루프 샷**: 안개·입자·조명 변화까지 얹은 2~3분 루프. 롱폼의 최소 단위를 검증하고, 이 단계에서 렌더 시간(1분 분량당 소요 시간)을 실측한다.
3. **첫 회차 전체**: 소재 회의부터 합성까지 파이프라인을 통과시켜 롱폼 1편 + 쇼츠 1편을 뽑는다.
