# simple-lama-inpainting은 setup.py에 numpy<2.0/pillow<10.0/opencv-python<5.0을 못박아 뒀다
# (2023년 배포 이후 갱신 안 됨). 위 하한(numpy>=2, pillow>=10)이 충돌 에러를 명시적으로
# 발생시키도록 강제한다. simple-lama-inpainting의 코드는 torch/numpy/PIL/cv2의 흔한 API만
# 쓰기 때문에, `--no-deps`로 설치하면 기존 최신 버전들과 함께 정상 동작한다:
#   uv pip install --no-deps simple-lama-inpainting
# (--no-deps 없이 설치하면 pillow가 9.5.0으로 다운그레이드되어 tests/test_depth.py가
# 깨질 수 있다 — pipeline/layers.py의 _get_lama() 함수가 numpy 버전을 확인하고
# 이 경우 명확한 에러를 던진다.)
#
# simple-lama-inpainting>=0.1.1 하한 필수: 0.1.0은 SimpleLama.__init__이
# `torch.jit.load(model_path)`를 map_location 없이 호출한다. 캐시된 체크포인트
# (~/.cache/torch/hub/checkpoints/big-lama.pt)의 data.pkl에 저장 시점 디바이스가
# "cuda:0"로 박혀 있어서, CUDA 없는 머신에서는 이 로드 자체가 torch 버전과 무관하게
# 항상 실패한다(NotImplementedError: ... 'CUDA' backend — 2026-09-02 실측: torch
# 2.2.2/2.6.0/2.7.1/2.8.0/2.13.0 전부 동일하게 실패, 즉 torch pin으로는 해결 불가였다).
# 0.1.1부터는 `torch.jit.load(model_path, map_location=device)`로 고쳐져 있고,
# device 기본값이 `cuda if available else cpu`라 CUDA 없는 머신에서 자동으로
# map_location="cpu"가 되어 문제가 사라진다. pipeline/layers.py의 _get_lama()는
# 이 상한 없는 패키지 코드를 그대로 쓴다(우회 래퍼 불필요) — 그래서 여기서 하한으로
# 강제한다: 0.1.0으로 되돌아가면(--no-deps 재설치 등) 조용히 같은 버그가 재발한다.
simple-lama-inpainting>=0.1.1
